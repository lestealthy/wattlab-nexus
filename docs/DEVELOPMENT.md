# Development Guide

How the codebase is organised and how to extend it safely.

## The golden path

```
edit firmware/src|include  ->  scripts\test.bat  ->  scripts\build.bat
```

The sketch folder `firmware/wattlab_nexus` is generated by
`scripts/sync-sketch.ps1` and its mirrored `.h`/`.cpp` are git-ignored. **Edit
the canonical `firmware/src` and `firmware/include` files only.**

## Build flow

1. `sync-sketch.ps1` mirrors `firmware/include/*.h` and `firmware/src/*.cpp`
   into `firmware/wattlab_nexus/`.
2. `arduino-cli compile` builds the sketch (Arduino only compiles sources that
   live inside the sketch directory).
3. The host build has no notion of a sketch: `run-tests.ps1` compiles the same
   canonical sources plus tests directly with g++.

## Adding a host-testable module

1. `firmware/include/nexus_foo.h`, `firmware/src/nexus_foo.cpp`.
2. Keep it hardware-independent. If hardware is needed, define a backend
   interface and provide a host implementation guarded by `#if defined(ARDUINO_ARCH_STM32)` for the device side.
3. Add `tests/unit/test_foo.cpp` with `int test_foo(void)`.
4. Register it in `tests/unit/test_main.cpp`.
5. Add the source + test to `scripts/run-tests.ps1`, and for the device to the
   firmware (it is picked up automatically once synced).

## Adding a hardware backend

Follow `nexus_storage_sd.cpp` / `nexus_rtc_stm32.cpp`:

- Implement a vtable/struct with function pointers or free functions.
- Guard the translation unit with `#if defined(ARDUINO_ARCH_STM32)` so the host
  build ignores it.
- Provide a host fake for tests.
- Register it with the service (`nexus_storage_select`, `nexus_time_set_rtc`).

## Memory and concurrency rules

- No dynamic allocation in ISRs or real-time loops.
- Keep DMA buffers in internal SRAM; if D-cache is enabled, add cache
  maintenance (see `MEMORY_MAP.md`).
- Never perform slow I/O on UI/capture/protocol tasks; enqueue and let the
  storage task drain.
- Use `nexus_err_t` return codes; never silently swallow errors.

## Coding conventions

- C++17, 4-space indentation.
- Bounded buffers and length-checked string operations.
- Comments explain why, not what.
- `-Wall -Wextra` clean.

## Testing conventions

- Pure functions: table-driven unit tests.
- Services: unit tests against the host backend.
- Cross-module: integration tests (`test_alpha_flow.cpp`).
- Fault paths: use the host backends' injection hooks
  (`nexus_storage_host_inject_write_failure`, etc.).

## Time discipline

- Wall clock: `nexus_time_*`. Monotonic: `millis()`/`micros()`/ticks.
- Never mix them. Timeouts and durations are monotonic; logs and filenames are
  wall clock.
